# TOUCHLINE ELEVEN

가상의 Royal Blue FC와 Crimson United가 경기하는 **11대11 3D 웹 축구 프로토타입**입니다. 두 팀 각각 골키퍼 1명과 필드 선수 10명이 실제 경기 루프에 참여합니다. React · TypeScript · Vite · Three.js · React Three Fiber · Rapier · Zustand를 사용합니다. 백엔드, API 키, 유료 에셋은 필요하지 않습니다.

> 구현과 자동 검증은 완료했지만, 제작 환경의 브라우저가 WebGL을 제공하지 않아 3D 렌더링·실제 키보드 플레이·게임패드·1080p FPS의 수동 검증은 완료하지 못했습니다. 상용 축구 게임 수준의 모션 캡처나 정교한 심판·전술 엔진은 아닙니다. 아래 제한 사항과 `TESTING.md`를 확인해 주세요.

## 1. 처음 실행하기

필요한 프로그램은 **Node.js 22 이상**, npm, WebGL 2를 지원하는 데스크톱 브라우저입니다. Chrome 또는 Edge의 하드웨어 가속을 켜 주세요. Node.js 설치 프로그램에는 npm이 포함됩니다.

GitHub에서 **Code → Download ZIP**을 눌러 내려받고 압축을 풉니다. 압축을 푼 프로젝트 폴더에서 터미널을 열어 다음 명령을 순서대로 실행합니다.

```bash
node -v
npm -v
npm install
npm run dev
```

터미널에 표시되는 주소(기본 `http://localhost:5173`)를 브라우저에서 여세요. 중단할 때는 터미널에서 `Ctrl+C`를 누릅니다. 처음에는 전·후반 각각 **1분**으로 설정해 조작을 익히면 편합니다. 기본 설정은 각각 5분입니다.

Git을 사용할 수 있다면:

```bash
git clone https://github.com/philosophyAIEDU/260906football.git
cd 260906football
npm ci
npm run dev
```

배포용 빌드와 미리보기:

```bash
npm test
npm run build
npm run preview
```

`dist` 폴더가 배포 결과입니다. `npm run preview`는 빌드한 파일을 확인하는 명령입니다.

## 2. Netlify 배포

이 프로젝트에는 `netlify.toml`이 포함되어 있습니다. Netlify에서 새 사이트를 추가하고 이 GitHub 저장소를 연결합니다.

| 설정 | 값 |
| --- | --- |
| Production branch | `main` |
| Base directory | 비워 두기 |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node.js | `22` |
| 환경 변수 / API 키 | 필요 없음 |

저장소 연결 후 배포를 실행하면 됩니다. SPA 새로고침을 위한 rewrite가 포함되어 있습니다. 직접 업로드할 경우 `npm run build` 후 **dist 폴더**를 업로드하세요. 이 작업에서는 GitHub 업로드와 Netlify 배포 준비까지만 수행하며 Netlify 사이트를 생성하지 않습니다.

## 3. 구현한 경기 기능

- 두 가상 팀, 고유 ID와 등번호를 가진 선수 22명, 골키퍼 포함 포지션별 AI.
- 메뉴 → 경기 소개 → 킥오프 → 전반 → 하프타임 → 진영 교체 → 후반 → 결과. 무승부, 재시작, 메뉴 복귀, 일시 정지.
- 4-3-3 기본 포메이션 및 4-4-2, 4-2-3-1, 3-5-2, 5-3-2. 여섯 전술 프리셋. 경기 중 일시 정지 → 설정에서도 변경 가능.
- 카메라 기준 이동, 가감속·회전 보간·전력 질주·체력·공 보호. 공간 격자로 선수 간 겹침 완화.
- Rapier 동적 공, 중력·잔디 저항·바운드·회전·CCD·선수와 골대 충돌. 짧은 속도 기반 터치로 드리블하며 공을 발에 고정하지 않음.
- 버튼 충전 패스·스루패스·크로스·일반 슛·감아차기·낮은 슛. 공중볼 가까이에서 높이에 따른 헤딩/발리.
- 패스 예상 위치 보조, 패스 경로 점수, 수비 가로채기, 공격 지원·침투·제한된 압박 인원.
- 골키퍼의 골문 위치 선정·예상 도착점 반응·캐치/쳐내기·배급. 확률과 반응 지연으로 선방 제한.
- 공 전체의 라인 통과 판정, 한 번만 득점 처리, 킥오프·스로인·코너·골킥·직접/간접 프리킥·페널티킥. 세트피스 준비 후 수동/자동 재개.
- 패스 시점 오프사이드 후보 기록, 수신 시 관여 판정, 반칙 위치 재개. 스로인·코너·골킥 등 재개에는 직접 수신 오프사이드 면제.
- 태클 거리·공 접촉·뒤쪽 접근을 이용한 단순화된 파울, 옐로카드·두 번째 경고 퇴장·위험한 태클 직접 퇴장. 퇴장 선수는 경기에서 제외.
- 방송·선수·전술 카메라와 짧은 득점 카메라. 관절형 선수, 잔디 줄무늬/노이즈, 경기장 라인·골대·골망·관중석·벤치·광고판·조명·점수 전광판.
- 선수 이름/포지션/등번호·체력·파워 HUD, Canvas 미니맵, 경기 사건 및 통계.
- 합성 관중 배경음·타격음·휘슬·환호, 사용자 시작 이후 오디오 활성화, 음량 설정.
- 그래픽 3단계, DPR 상한, 인스턴스 관중, UI 약 10Hz 및 미니맵 약 12Hz 갱신, 탭 비활성화 시 자동 일시 정지.

## 4. 조작 방법

이동은 **공격 방향이 아니라 화면 방향** 기준입니다. 후반에 진영이 바뀌어도 오른쪽 키는 화면 오른쪽으로 움직입니다.

| 동작 | 키보드 | 표준 게임패드 |
| --- | --- | --- |
| 이동 | 방향키 ↑ ↓ ← → | 왼쪽 스틱 |
| 전력 질주 | W (또는 Shift) | RB |
| 패스 | S | A |
| 스루패스 | — | Y |
| 롱킥 | A | X |
| 슛 / 공 없으면 태클 | D | B |
| 공 보호 / 스탠딩 태클 | — | RT |
| 선수 전환 | Space / Tab | LB |
| 카메라 전환 | C | 키보드 사용 |
| 슛 방향 지정 | 이동 방향 | 오른쪽 스틱 |
| 일시 정지 | Esc | Start |

패스·크로스·슛은 **누르고 떼면** 실행됩니다. 오래 누를수록 강해지지만 과한 충전은 슛 정확도를 낮춥니다. 방향 입력 없이 슛하면 골문 쪽으로 조준합니다. 세트피스는 약 2초 준비 후 입력할 수 있고, 입력이 없으면 약 10초 안에 자동 재개합니다. 골킥이나 스로인도 패스 키를 사용하세요.

패드가 없으면 키보드로 작동합니다. 패드는 브라우저에서 버튼을 한 번 누르면 감지됩니다. 표준 Gamepad API 매핑이며 실제 패드 장치 테스트는 미완료입니다. 모바일은 메뉴·결과 레이아웃만 대응하며 터치 경기 조작은 없습니다.

## 6. 에셋 교체

기본 게임은 모델·텍스처·음원 다운로드 없이 실행됩니다. 선택형 에셋은 **사용 권한이 있는 파일**만 추가해 주세요. 경로의 대소문자는 정확히 일치해야 합니다.

| 에셋 | 파일 예시 | 연결 위치 |
| --- | --- | --- |
| 선수 모델과 내장 애니메이션 | `public/assets/models/player.glb` | `src/data/assets.ts` → `playerModel: '/assets/models/player.glb'` |
| 애니메이션 클립 이름 | GLB 파일 내부 | 같은 파일의 `animationMap` |
| 홈·원정 유니폼 텍스처 | `public/assets/textures/home.png`, `away.png` | `uniformTextures: ['/assets/textures/home.png','/assets/textures/away.png']` |
| 잔디 텍스처 | `public/assets/textures/grass.jpg` | `pitchTexture: '/assets/textures/grass.jpg'` |
| 관중 배경음 | `public/assets/audio/crowd.ogg` | `audio.crowd` |
| 킥·슛·휘슬·환호·골대·태클·UI 효과음 | `public/assets/audio/*.ogg` | `audio.kick`, `shot`, `whistle`, `goal`, `post`, `tackle`, `ui` |

모델은 미터 단위·키 약 1.8m·발바닥 Y=0·정면 +Z를 권장합니다. `modelScale`과 `modelRotation`으로 보정합니다. `AnimatedModel.tsx`가 skeleton을 선수별로 복제하고 `AnimationMixer`로 재생·크로스페이드합니다. 내장 클립 이름이 다르면 `animationMap`을 맞춰 주세요. 없는 클립은 첫 클립으로 대체됩니다. 모델 로딩 실패는 관절형 기본 모델로 대체합니다.

유니폼 자동 텍스처 설정은 **기본 선수의 상의 패널**에 그려집니다. 이미지는 몸통 UV 영역에 맞춰 늘어나며, 등번호·이름·엠블럼은 그 위에 다시 그립니다. 외부 GLB의 특정 유니폼 메시/머티리얼은 모델마다 이름·UV가 달라 `AnimatedModel.tsx`의 `model.traverse`에서 별도 연결해야 합니다. 등번호·색상 구분도 외부 모델에 맞게 지정해 주세요. 기본 잔디는 반복 텍스처이므로 타일 가능한 이미지를 사용하세요. 음원 로드/재생 실패 시 합성 효과음으로 대체합니다. UI 효과음 인터페이스는 준비되어 있지만 모든 메뉴 버튼에 연결되어 있지는 않습니다.

## 7. 그래픽과 성능

메뉴 또는 일시 정지 → 설정 → 그래픽 품질을 선택하세요.

- 낮음: 그림자 끔, DPR 1, 관중석 점유율 30%(약 3,500명).
- 중간: 그림자 2048, DPR 최대 1.4, 관중석 점유율 62%(약 7,300명).
- 높음: 그림자 4096(PCF Soft), DPR 최대 1.9, 관중석 점유율 88%(약 10,400명).

22명 외의 관중은 InstancedMesh 한 개로 그립니다. 선수 22명은 지오메트리 하나를 공유하고 스켈레톤과 유니폼 텍스처만 개별로 갖습니다. 골망은 타일링 텍스처 패널이며 천 물리를 사용하지 않습니다. 그래픽 세부 LOD 및 프러스텀별 애니메이션 갱신 빈도 조절은 아직 구현되지 않았습니다. **1920×1080 50~60 FPS는 목표이며 실측 보장이 아닙니다.**

Rapier의 내장 WebAssembly 때문에 physics 번들이 약 2.4 MB(압축 약 0.9 MB)로 큽니다. Vite의 큰 청크 경고는 남지만 TypeScript/빌드는 성공합니다. 외부 폰트가 차단되면 시스템 글꼴로 표시됩니다.

## 8. 현재 제한 사항

- 사람 같은 정교한 모션 캡처가 아닌 코드 기반 스킨드 선수입니다. 손가락·얼굴 표정·옷 주름 시뮬레이션은 없습니다. 모든 애니메이션 타입이 서로 다른 완전한 동작 클립을 갖고 있지는 않습니다. 골망 변형·리플레이·선수 교체·연장전·승부차기는 없습니다.
- 공격/수비/전술은 제한된 상태와 점수 기반 휴리스틱입니다. 모든 명세의 전술 행동·능력치가 개별적으로 완전 구현된 것은 아닙니다. 퇴장 후 가까운 동료가 공간을 보완하며 전문적인 재편성 엔진은 아닙니다.
- 헤딩/발리는 공 높이와 거리 기반이며 정밀한 점프 경합·손/발 단위 충돌·개인기는 단순화되어 있습니다. 키보드는 방향키와 S·D·A를 중심으로 사용합니다.
- 골키퍼는 거리·궤적·반응 시간·능력치 기반 근사이며 실제 관절의 손 접촉 판정이 아닙니다. 잡은 공은 발 앞 배급 위치로 옮깁니다.
- 오프사이드는 패스 시점 후보와 직접 접촉을 판정합니다. 시야 방해·간접 관여·세밀한 굴절/의도적 플레이 해석은 없습니다. 어드밴티지·핸드볼·VAR·부상·추가 시간·교체 규정도 없습니다.
- 파울/카드는 단순화된 거리·방향·속도 판정입니다. 세트피스 선수 위치와 벽·페널티 절차, 직접 재개 득점 제한은 프로토타입 수준이며 국제 규칙 전체 인증을 의미하지 않습니다.
- 유효 슈팅은 발사 궤적의 골문 예상 통과와 실제 득점을 기준으로 계산합니다. 굴절·블록·자책골의 기록은 실제 경기 통계 기관과 다를 수 있습니다.
- 게임패드와 GPU 브라우저 실기 검증이 필요합니다. WebGL 없는 환경에서는 실행 버튼 대신 안내를 표시합니다. 브라우저 전체 수동 완료 기준을 충족했다고 주장하지 않습니다.

## 디자인 업데이트

참고 경기 이미지에 맞춰 방송 시점을 가까이 낮추고 선수 비율과 실루엣을 개선했습니다. `src/entities/AthleticRig.tsx`는 분리된 무릎·팔꿈치, 속도 연동 보폭, 상체 기울임, 목·얼굴·헤어·유니폼 패턴·양말·축구화를 표현합니다. 기본 모델의 공유 지오메트리와 GLB 교체 경로를 유지했습니다.

잔디는 1024px 절차적 질감과 범프·이방성 필터링을 사용하고, 경기장 라인은 실제 폭의 메시로 표현합니다. 선택 선수에 초록 화살표·발밑 체력 표시를 추가했습니다. HUD는 상단 왼쪽 방송 점수판과 작은 반투명 패널로 변경했습니다. 실제 GPU 화면의 시각적 검수는 WebGL 제약 때문에 미완료이며, 사진급 실사 모델이나 참고 게임의 원본 에셋을 사용한 것은 아닙니다.

## 크기·카메라·간편 조작 업데이트

공의 반지름을 0.22m에서 0.11m로 수정했습니다. 렌더링과 Rapier 충돌체·골라인 판정이 같은 상수를 사용하며, 기본 선수 모델은 1.04배로 표시합니다. 화면 오른쪽 **카메라** 버튼에서 중계/선수 뒤/전술 시점을 고르고 거리와 높이를 슬라이더로 조절할 수 있습니다. C로도 시점을 순환합니다.

우리 팀이 공을 받거나 빼앗아 소유하면 해당 선수(골키퍼 포함)로 자동 전환합니다. 상대 선수나 오프사이드로 판정된 수신 선수에게는 자동 전환하지 않습니다. 방향키로 이동하고 S로 패스, D로 슛(공이 없으면 태클), A로 롱킥을 합니다. 키 안내는 경기 화면 하단에 항상 표시됩니다. 패스·슛·롱킥은 누른 뒤 떼면 실행됩니다.

## 선수 형태 및 근접 자동 전환 업데이트

`humanGeometry.ts`에 어깨·허리·턱·허벅지·종아리 윤곽을 가진 연속 단면 메시를 추가했습니다. 기존 기본 도형 중심 표현을 개선하고 속도에 따른 보행 주기와 킥/달리기 전환 보간을 적용했습니다. 여전히 절차적 캐릭터이며 스캔 기반 실사 인물이나 모션캡처 모델은 아닙니다. GPU 시각 검증 제약도 남아 있습니다.

공이 소유되지 않은 상태에서 6m 안의 우리 팀 선수가 예상 공 위치에 확실히 더 가까우면 조작 대상을 자동으로 바꿉니다. 1.2m 이상의 접근 이점과 0.65초 전환 간격을 적용합니다. 오프사이드 후보·퇴장 선수는 제외합니다. **Space**(또는 Tab)로 직접 전환하면 근접 자동 전환은 1.5초간 기다립니다. 실제 우리 팀 공 소유가 발생하면 해당 선수로 즉시 전환하는 동작은 유지됩니다. 하단에 수동 전환 안내도 표시됩니다.

## 외형·난이도·W 달리기 업데이트

둥근 어깨 덩어리를 제거하고 소매·골반·손·축구화에 각진 단면을 적용했습니다. 머리와 팔다리의 폭을 줄여 풍선 같은 부피감을 완화했습니다. 여전히 절차적으로 제작한 모델이며 실사 스캔/모션캡처 캐릭터가 아닙니다. 실제 GPU 화면의 시각적 품질 검수는 미완료입니다.

메뉴뿐 아니라 경기 화면 왼쪽 **난이도** 선택과 일시 정지 설정에서 쉬움/보통/어려움을 변경할 수 있습니다. 신규 설정의 기본은 쉬움이며 기존 사용자의 저장된 선택은 유지합니다. 쉬움은 상대 판단 간격·압박 거리·태클 빈도·슈팅 정확도·골키퍼 반응과 선방 확률을 낮추며, 사용자 팀 동료의 판단은 보통으로 유지합니다. **방향키를 누르며 W를 유지하면 전력 질주**하며 놓으면 일반 달리기로 돌아옵니다. Shift와 패드 RB도 유지합니다.

## 3D 모델·경기장 그래픽 업데이트

선수를 **스킨드 메시**로 다시 만들었습니다. `playerBody.ts`가 골반·척추·가슴·목·머리·양팔·양다리 17개 본과, 관절마다 가중치를 섞은 연속 표면을 생성합니다. 부위별 강체를 늘어놓던 이전 방식에서 생기던 관절 틈이 사라지고 무릎·팔꿈치·어깨가 부드럽게 접힙니다. 지오메트리는 22명이 공유하고 스켈레톤만 개별로 만듭니다.

`kitTexture.ts`는 선수마다 512px 아틀라스를 그립니다. 상의(세로줄/가로띠·칼라·소매), 등번호와 이름, 가슴 번호와 엠블럼, 반바지, 양말과 트림, 축구화와 밑창, 얼굴(눈·눈썹·코·입)·머리카락·피부색·골키퍼 장갑이 한 장에 들어가며 재질과 드로우콜은 선수당 하나입니다. 키·체형·피부·머리색·축구화 색은 선수 번호에서 결정론적으로 파생합니다.

`playerAnimator.ts`가 매 프레임 목표 포즈를 만들고 각 관절을 감쇠 보간합니다. 속도에 따른 보폭·상체 기울임·골반 회전·팔 스윙, 백스윙에서 임팩트까지의 킥, 슬라이딩 태클, 헤딩 점프, 골키퍼 준비 자세와 다이빙, 골 세리머니를 다룹니다.

경기장도 다시 만들었습니다.

- 잔디: 경기장 전체를 덮는 2048px 컬러맵(잔디 깎기 줄무늬·골문 앞 마모·색 편차)과, 촘촘히 반복하는 잔디 노멀맵을 함께 사용합니다.
- 골대: 골망이 선분이 아니라 타일링 그물 텍스처 패널이며, 뒤쪽 지지대와 그림자를 갖습니다.
- 관중석: 계단식 좌석 데크(디딤판=좌석 텍스처, 챌판=콘크리트), 지붕과 트러스 기둥, 좌석 격자에 앉은 관중, 홈·원정 응원석 색 구분, 득점 시 기립.
- 그 밖에: LED 광고판, 전광판 점수 표시, 조명탑, 벤치, 코너 깃발, 하늘 돔과 그 하늘로 만든 IBL 환경광, ACES 톤 매핑, PCF Soft 그림자.
- 공: 정이십면체 꼭짓점·면중심의 보로노이로 오각형/육각형 패널과 솔기를 계산해 텍스처와 범프로 사용합니다. 공중에 뜬 높이에 따라 흐려지는 접지 그림자를 추가했습니다.

HUD는 점수판 대비를 높이고 미니맵을 새로 그렸으며(잔디 줄무늬·페널티 박스·공 글로우), 하단 조작 안내를 알약 형태로, 화면 가장자리에 옅은 비네트를 넣었습니다.

절차적으로 생성한 모델과 텍스처이며 사진급 스캔 에셋이나 모션 캡처가 아닙니다. 검수는 SwiftShader 소프트웨어 렌더링 스크린샷으로 진행했으므로 실제 GPU에서의 프레임 성능은 별도 측정이 필요합니다.

## 실제 사람에 가까운 선수 모델 업데이트

선수 지오메트리와 유니폼 아틀라스를 다시 만들었습니다.

- **비율**: 키 1.80m에 머리 크기를 약 1/7.7로 잡았습니다. 이전 모델은 머리가 커서 인형처럼 보였습니다. 어깨 너비, 가슴 두께, 다리 길이 비율(신장의 약 52%)도 성인 남성 기준으로 맞췄습니다.
- **단면 조형**: 단면마다 각도별 반지름 배율을 줄 수 있게 해서, 삼각근·등의 척추 홈·광배근·둔근·대퇴사두근·종아리·정강이 평면, 그리고 턱선·광대·코·눈두덩·뒤통수·귀를 실루엣에 넣었습니다. 이전에는 모든 단면이 단순 타원이었습니다.
- **목과 옷깃**: 상의가 목까지 덮여 머리가 어깨에 바로 붙어 보이던 문제를 고쳤습니다. 옷깃 위는 피부로 칠하고, 승모근에서 목이 솟는 단면을 추가했습니다.
- **머리카락**: 앞머리 아래쪽 링이 두개골 안쪽에 들어가는 닫힌 캡으로 바꿨습니다. 헤어라인이 열린 모서리가 아니라 교차선으로 생겨 옆에서 봐도 판때기 같은 단면이 보이지 않습니다.
- **얼굴**: 눈두덩 그림자, 흰자와 홍채·동공, 윗눈꺼풀 그림자, 눈썹, 코 옆면과 콧구멍, 입술선과 아랫입술 하이라이트, 구레나룻을 그립니다.
- **번호 위치 수정**: 등번호와 이름이 등 중앙이 아니라 **왼쪽 옆구리**에 찍히고 있었습니다. 링 각도 0이 정면인데 텍스처는 등으로 가정한 오류였습니다. 정면·등 위치를 상수로 내보내 양쪽이 같은 기준을 쓰도록 고쳤습니다.
- **재질**: 컬러 외에 **노멀맵과 러프니스맵**을 추가했습니다(골키퍼/필드 2종을 22명이 공유). 상의·반바지 주름, 양말 골지, 축구화 끈과 밑창 트레드, 머리카락 결이 빛을 받고, 피부·원단·양말·가죽이 서로 다른 광택을 갖습니다. 겨드랑이·옷깃 아래·바지 밑단·무릎 뒤·턱 밑 음영은 컬러맵에 구워 넣었습니다.
- **자세**: 서 있을 때 팔꿈치가 자연스럽게 굽고 팔이 몸통에서 약간 벌어집니다. 골키퍼 준비 자세의 무릎이 앞으로 굽도록 고쳤습니다.

여전히 코드로 생성한 모델입니다. 스캔 기반 실사 인물이나 모션 캡처가 아니며, 얼굴 표정·손가락·옷 주름 시뮬레이션은 없습니다.
